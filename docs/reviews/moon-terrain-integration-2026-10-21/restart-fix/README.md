# 193秒接点回跳与停帧修复

日期：2026-10-22。用户反馈接点停住、又从头开始后，重新在本项目微信开发者工具原生模拟器里复现。上一版只验证了原速路径，漏掉加速后恢复原速；上一版“完整用户路径验证”的结论不充分。

## 已复现的原因

左下角原有长按10倍速只推进镜头累计时间，音乐继续原速。新接入的音频时钟在松手恢复1倍速时，直接重新采用音乐较早的时间。

实际长按19秒后，尾段已在193.3147秒进入；松手后计时回到了30.2613秒，随后35.2747秒。尾段依然激活，相机路径把小于193秒的时间限制到193秒，于是看起来卡在远景首帧。记录见 `original-accelerated-release-ax.txt`、`original-accelerated-stalled.jpg`。同一份旧代码的原速路径则能自然结束，不能据此排除这条操作路径的故障。

## 修复

恢复原速时，使用同一个原播放器的 `seek()` 定位到当前镜头时间。异步定位期间保留目标时间，旧音频样本不再接管镜头；定位完成后继续跟随音乐。原生时间瞬间归零或返回明显过期样本时，镜头不回退。新一轮起航重置定位状态。

定位开始时清掉旧歌词定时器，完成后按实际音乐位置重新排程；没有重开音频、替换音轨或改动已确认镜头、人物、地形和云素材。新增有限容量的开发者工具本地诊断，只写小程序本地存储，不向云端发送。
