## 问题1：可选旅行者阻塞起航

`miniprogram/pages/gl/moon-voyage-assets.js:117-122` 的同一个 Promise.all 同时等待两个必需月球分包、原音乐以及 `_companionFx.preload()`。

`moon-voyage-encounters.js:72-90` 中 preload 会启动其他模型，但返回的是 Voyager 的分包、geometry.bin、四张贴图和构建 promise。此分支没有应用层超时；必需资源全部完成后，只要 Voyager 尚未完成，“登船准备中”仍不会结束。其他机器人/星舰/高达/EVA启动后不进入该返回promise，不能把它们误说成全部都被等待或全部不被等待。

本轮通过 VM 装载真实 preloadAssets，使用受控延迟模拟可选 Voyager：必需分包与音乐成功后仍不完成；放行 Voyager 后才完成。并发两次调用只下载一次音乐，loaded重用也没有重复下载。

建议：起航门槛只保留必需月球与音乐；可选模型后台加载，有加载预算和自己的可见性兜底，失败不阻塞原航程。当前未实施。

## 问题2：显露前没有完成全部GPU准备

`moon-terrain-sequence.js:42-45` 使用 renderer.compile 标记 ready；实际随项目打包的 Three r108 中 compile 遍历灯光和材质初始化，不负责完整场景的纹理上传/几何首次绘制/阴影首次渲染。因此月面仍可能在193秒初次绘制时支付这些成本；局部近景贴图具体何时上传取决于对应材质首次被绘制，不能只看下载完成时间。

此外，`moon-terrain-sequence.js` 的 enter() 在193秒才为月球球体追加原月球的 onBeforeCompile，并设 needsUpdate；这一最终材质变体也不属于前面的ready预编译状态。

`moon-keepsake.js:59` 调用 `renderer.initTexture?.(texture)`，但当前打包的 Three r108 没有 initTexture，此处为安全跳过。照片纹理首次真正采样在显露时；`moon-keepsake.js:64-74` 也直到266.94秒才把2×2 render target扩大为实际尺寸并首次使用。

这些是代码确定的准备缺口，不代表已经量到真机掉帧。建议：在进入登月后的后台阶段，用当前r108支持的离屏实际绘制完成预热，并分帧安排，显露前准备正确尺寸目标；所有renderer状态须完整恢复。当前未实施，未改镜头或照片。
