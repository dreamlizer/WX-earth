# 登月体验精修执行方案：相遇、光与回望

日期：2026-10-20。状态：**方案草案，未实施、未播放验证。**

本轮仅整理执行与验收方案。下述读云数据、试听、调参、代码修改、编译与真机检查均为后续工作，不能据此视为已经执行。当前不上传、不发布、不修改云端歌词。

## 1. 目标与交付范围

保留“离地—旅行者号掠过—机器人同行—高达超过—星舰赴月—绕月—回望地球”的故事。增强三个感受：旅伴在回应观众、阳光来自可信的空间方向、旅程最终真正安静下来。

首轮不增加角色、模型、贴图或依赖，不恢复着陆试航。保留正式入口、现有资源分包及普通/禅定/登月三条路径。

实施采用三个可独立比较的改动批次，最后再决定是否加入点缀：

1. 歌词/音轨基准核对、终景停驻与间奏留白。
2. 机器人回望与相遇之间的视觉停顿。
3. 太阳散光、星流与星座的轻重关系。
4. 可选：旅行者号材质反光；月面微光呼应仅作条件成立后的候选。

交付物为局部代码差异、必要回归测试、同条件前后对比、连续播放记录和简短验收表。独立成片、片头片尾、上传与发布不属于本方案首轮交付。

## 3. 第一步：锁定歌曲与比较基准

后续实施前先完成以下必要准备，不先调整所有效果：

- 记录当前工作区差异，保存本次会修改文件的基线副本或补丁；保留用户其他未提交工作，不用整个仓库回滚制造基线。
- 通过现有只读通道核对正在使用的 `Zen-moon.mp3` 版本、真实总长，以及运行实际读取的预设999内容和来源。记录音轨指纹及歌词快照，不记录凭据或用户数据。
- 对实际歌曲标注首个人声、各段人声结束、两段长间奏、最后一句开始/结束、音频结束。只复核与本方案有关的乐句，不另建整套转录系统。
- 自然播放时记录音频currentTime与镜头时间在约30、70、113、180、最后一句附近的差值；对应字幕抽查可见时间。调试跳时不能证明音画同步。
- 在同一目标手机、同一亮度设置下留存基线关键片段；整段正常速度播放一次，兼作首次同步检查。

本地 `诗句_英文版_时间轴样本.json` 仅作候选基准：首句26.07秒；两处长显示区间82.50–123.55秒、180.27–221.20秒；末句253.37–262.84秒。显示区间不等于人声时长，更不等于已确认的间奏范围。

准备过关：确认实际版本和末段可用时长；前后段音画差值没有持续扩大。建议以关键点偏差不超过约0.3秒为排查线，连续播放无可辨错位作为最终判断。

若出现可复现漂移：先修登月范围内的时钟基准，使正式播放的镜头和歌词依据同一音频进度；调试跳时单独处理。缓冲、音频尚未开始和退出时不让视觉自行跑走。只在证据确认后实施此修复，不为本次审美工作重构其他歌曲播放器。未解决前不宣称精确歌词卡点通过。

## 4. 工作包A：终景停驻和歌词留白（最高优先级）

### 具体做法

1. 首选保留113–243秒绕月位置、朝向、太阳和地球位置，最终推近仍从243秒起步。
2. 初版尝试把18秒推近缩为10秒，于253秒停稳；起止速度均为零，避免突然冲向月球。到达后不再新开镜头，只保留原有轻微自转与云层运动。
3. 若10秒版本显得急，改为12秒，于255秒停稳；按当前歌词样本仍可留下约7.8秒。目标是最后有6–10秒可观看的稳定终景，实际以音轨为准。
4. 若两版都急或实际音轨不留余量，不硬压速度。交付对比后再设计局部提前收束；首轮不自动改写0–243秒路线。
5. 地球朝向使用独立的原基准，避免单改 `finalApproachSec` 导致前面全部朝向随之偏移。终景地球大小、位置和月面右侧受光关系沿用现有构图。
6. 核对两处约41秒歌词显示：仅在人声确实结束后，约0.4–0.8秒内退场；下一句按真实起点进入。不能给所有长句统一截断，不修改正常长音。
7. 字幕沿用现有原生覆盖层、字体和安全区域。先在隔离的预设999测试副本验证时长；选定后记录实际应改的来源。云端写入另按授权执行，不能把未部署的本地样本当作生效。

### 控制点

`moon-voyage-timeline.js`、`moon-orbit-sequence.js`；必要时 `moon-voyage-lyrics.js`。歌词数据以核对后的真实来源为准，不改其他预设。

### 怎样验证、怎样过关

- 同条件对比243秒至曲末的原版、10秒版；仅当10秒版过急时制作12秒版。
- 以最后一句前至少一个完整乐句开始正常速度播放，听觉和镜头一起判断，不能只看253秒截图。
- 最终有6–10秒稳定观看时间；地球中心不继续游走，月面不突然放大或停顿，歌词可完整读完，最后的人声没有被退出流程切断。
- 间奏留白以真实人声结束为前提；空窗内没有旧歌词悬挂，下句不漏、不重复、不提前消失。
- 自动检查原绕月0–243秒保留、推近连续、相机不穿月、地球不瞬移/被月面错误遮挡、退出资源回收。

不通过示例：为抢出停留时间而产生冲刺感；月球面积增加后挤掉地球或歌词；停稳不到一秒就退出；只改样本而运行仍用旧缓存。

## 5. 工作包B：机器人回望与段落呼吸

### 具体做法

- 保留47秒入场和既有接近路径，保持原有整体转身角度作为初版基线，先调节动作时序。
- 候选动作安排按实际旅程时间：约59–62.5秒缓慢回望，62.5–66秒保持可辨的回应，66–73.5秒逐步转回前方，然后沿原路线离开。精确起点随实际歌曲乐句微调。
- 先确认“身旁同行—回望—停一下—面向前方—离去”可以一次看懂。不得把手臂轻摆扩大为夸张挥手，也不加入未经验证的头部骨骼动作。
- 回望时只尝试把近景星流亮度/拖尾存在感降低约15%–25%，渐入渐出各约2秒；保持粒子运动速度连续，不恢复过去被否定的星流停住。
- 保留42–47秒无新角色的间隔。
- 92秒星舰入口首轮不后移。高达退出后，优先收轻背景，以既有巨大舰体缓慢露出形成节奏变化；只有连播证实仍拥挤时，才小幅调整92–96秒的露出曲线，并保持112.35秒抵达节点。
- 113–119秒作为近月安静窗口：不出现新角色，压下星座名称/连线，保留月面和远星；原镜头继续流动，不做冻结画面。

### 控制点

`moon-voyage-encounters.js`、`moon-voyage-robot.js`、`moon-voyage-star-flow.js`；星座窗口由 `moon-voyage-timeline.js` / `moon-voyage-zodiac.js` 控制。

### 怎样验证、怎样过关

- 看42–92秒有声原速片段：不预先说明动作意图，仍能看出机器人朝观众回望、停留、再转走。
- 至少有约2秒以上清楚可辨的回应，动作不中断飞行；轮廓和脸部朝向不被暗部、裁边或字幕遮住。
- 机器人回望期间背景仍有前行感，亮度包络没有被感知成闪一下或画面突然变空。
- 78–120秒连续看一次：高达、星舰、抵达星芒各有独立重点；113秒后能明显感到舒缓。
- 自动检查动作连接连续、整机可见、粒子运动连续、固定时刻重播一致，以及原高达/星舰节点和清理不退步。

不通过示例：像原地掉头表演；一直摆动像挥手；机器人与高达争夺同一中心；离场用硬隐藏补救；通过停止星流制造“等待”。

## 6. 工作包C：太阳、月面与星空层次

### C1 太阳散光

- 保留现有太阳世界方向、月球遮挡判断和103–113秒照明交接，不新增太阳实体、不换全局曝光掩盖问题。
- 用当前几何产生的两次掠光窗口调节包络。初版保留约10秒范围，采用柔和起落；第一处峰值先试当前效果的40%，第二处65%。这些是候选参数，不是验收阈值。
- 保留暖白色，弱化满屏均匀泛白；光源侧最明显，离光源较远的空间仍能辨认黑色和星点。
- 让已有固定光照与相机运动自然显示月面细节，再由散光加强该感受，不额外让月球整体发光，也不加一圈大气光边。
- 只有飞行器—近月交接仍有明确色温割裂时，才局部微调飞行器材质光；不顺手重做高达装甲和所有材质。

过关：光的出现、增强、退去可辨但不抢走月球；亮面坑纹仍可辨，远处地球不被洗白；月球遮挡光源时散光消失；两次掠光有轻重区别；退出后其他模式亮度恢复。

验证：两次掠光分别提前5秒开始、延后5秒结束原速播放，另看103–119秒衔接。关键帧对比取无散光、渐入、峰值、渐出四帧，来源必须是同一微信运行条件。截图只用于看层次，不能代替动态判断。

### C2 星空与星座

- 保留既有远星背景；近景星流仍负责飞行速度，不增加总数量。检查现有近景星流淡出与近月安静窗口是否自然，仅在突兀时修改其包络。
- 星座“星点、连线、名称”分别调度。到达和回望地球期间，关闭名称与连线的强调；不要让整个背景随着它们开关突然变亮或变暗。
- 初版只做一次发现窗口，候选126–136秒，与样本中再次描绘群星的乐句接近。先核对原轨道此时实际可见的星座，再选定；若取景不合适，顺延到真实可见且不与地球重现/掠光冲突的乐句，不把星座拖到相机前。
- 候选包络：约2秒渐入、3秒可辨、3秒退去；连线峰值先试0.04–0.06，名称首轮隐藏，退去后原星点仍在。
- 此窗口最多强调一个星座。其余星座原位置保留，不一起轮播、闪烁或增加说明卡片。
- 如需定点复现，新增的包络使用绝对旅程时间。原星座旋转为累加dt；只有需要比较其具体位置时，才在该模块内改成等价的绝对时间姿态，避免跳时后错位。

过关：看起来是从已有星空里辨认出形状；退场后星空仍连续。月球、地球和歌词出现时具有更高注意力；不出现科普标签墙，不用彩色云雾填满黑色空间。

## 7. 可选点缀：先判断必要性，再实现

### 旅行者号的一次材质反光

仅在前三个工作包通过后考虑。用现有金属材质和自转，挑选接近时刻让一处边缘约0.5–1秒接住高光。优先调整该材质粗糙度/高光响应，不添加贴屏闪点，不把模型整体提亮，不改变已确认的近距离轨迹。

通过条件：反光附着在真实表面，转动后自然消失；正常观看不遮住结构，不盖过歌词；即使观众没注意到，也不影响故事。若调整会损害整段材质，保留原版。

### 月面微光呼应

首轮默认不做。先确认最终镜头能看见星舰真正抵达的同一片月面；位置必须跟随月球且受深度遮挡，不能透过月球显示。成立时才试一个小而稳定的点，且不延长原抵达星芒、不给终景加闪烁。

通过条件：不能比地球醒目，不像故障像素；前后可解释为同一地点。空间或审美不成立就取消，不调整终景迁就彩蛋。

## 9. 验收方法和证据

### 9.1 自动检查

改JS后运行项目规定的全部测试：

```bash
for f in tools/*.test.cjs; do node "$f"; done
```

另做diff检查。复用 `moon-encounters`、`moon-robot`、`moon-original-earth`、`moon-light-continuity`、`moon-voyage-lifecycle` 等现有测试；只有新行为未覆盖时才补测试。

重点保护：曲线连续、原轨道与光照边界、地球固定位置、歌词空窗/切句/退出取消、重播一致、遮挡、资源清理和异步重入。

已有测试包含“两次散光均为同样10秒线性强度”和“终景261秒”等旧具体约定。新方案改变的部分要改为新行为断言，并保留遮挡、连续性、恢复等保护，不能删除失败测试来获得通过；未被本方案改变的原轨道/灯光约束继续保持。

### 9.2 微信开发者工具

识别当前 `wx-earth` 项目窗口，只做普通编译，不反复重启、不干扰其他项目。先记录原有日志，检查本次是否新增错误。

定点截图用来核对构图、字幕、安全区、明暗；原速有声片段用来判断回望、速度、光效和歌词节奏。直接写 `_accumTime` 或10倍速只允许定位，不能当作音画同步证据。

现有 `tools/moon-review-server.cjs` 只作辅助地月几何检查。其独立材质、历史贴图与gamma设置和当前小程序不完全相同，不作为本轮亮度验收面；也不为本方案先重做此工具。

### 9.3 目标真机

在用户主要使用的手机上看最终完整旅程，至少确认以下结果：
